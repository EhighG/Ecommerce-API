# 업무 규칙

이 서비스는 구매자와 판매자가 있는 오픈마켓형 이커머스의 서버다. 결제와 채팅은 범위 밖이고, 배송은 상태 변경만 다룬다. 배송지 정보는 없다.

용어(주문, 주문항목, 주문 수, 스냅샷, 발급 쿠폰 등)의 뜻은 [`CONTEXT.md`](../CONTEXT.md)에 있다. 규칙이 코드와 다른 곳에는 "현재는 ~"으로 지금 동작을 함께 적었다.

## 사용자와 역할

- 역할은 `BUYER`, `SELLER`, `ADMIN` 중 하나이고 바뀌지 않는다. 역할을 바꾸는 기능은 없다.
- 가입할 때는 `BUYER`나 `SELLER`만 고를 수 있다. `ADMIN`으로 가입하려 하면 400이다. 관리자 계정은 운영자가 DB에 직접 넣는다.
- 이메일은 전체 사용자(탈퇴자 포함) 중에서 유일하다. 탈퇴한 사람의 이메일로는 다시 가입할 수 없다. 닉네임은 겹쳐도 된다(최대 20자).
- 비밀번호 규칙은 [`security.md`](security.md)에 있다.
- 탈퇴는 숨김 삭제다. 탈퇴한 사용자는 로그인할 수 없고, 프로필 조회와 작성자 기준 리뷰 조회에서 404가 된다.
- 탈퇴한 사용자의 닉네임은 공개 화면(리뷰 등)에서는 가리고, 거래 당사자 화면(판매자의 주문항목 목록 등)에서는 그대로 보여 준다.
- **판매자 탈퇴**: 자기 상품에 `주문완료`나 `배송중` 상태인 주문항목이 하나라도 있으면 거절한다(403). 통과하면 그 판매자의 모든 상품을 아래 "상품 삭제" 규칙대로 한 번에 삭제한 뒤 탈퇴 처리한다.
  - 현재는 검사와 상품 삭제 사이에 들어온 주문은 막지 못한다(`docs/tracking/findings/auth-user.md`).
- **구매자 탈퇴**: 진행 중인 주문이 있어도 허용한다(의도된 규칙). 구매자의 주문은 그대로 남는다.
- 비밀번호 변경과 탈퇴는 현재 비밀번호를 확인한 뒤 처리한다. 성공한 뒤 어떤 세션이 끊기는지는 `security.md`의 "세션 종료"에 있다.

## 상품

- 상품은 판매자가 등록한다. 등록할 때 재고 행 1개와 통계 행 1개가 함께 만들어진다. 이 둘이 없는 상품은 비정상 데이터다. 어느 한쪽이라도 없으면 목록에서 빠지고 상세는 '없음'이 된다. 재고 행이 없으면 주문은 재고 부족으로 거절되고, 재고 수정이나 취소는 서버 오류가 난다. 통계 행이 없으면 주문, 취소, 리뷰 작성·수정이 서버 오류가 난다.
- 수정할 수 있는 항목은 설명(1~1000자, 공백만은 불가), 단가(0 이상), 이미지뿐이다. 상품명과 카테고리는 바꿀 수 없다.
- 단가를 바꿔도 이미 만들어진 주문항목에는 영향이 없다(스냅샷). 장바구니의 금액은 항상 현재 단가로 계산한다.
- **이미지**
  - 이미지는 0~n장이고, 판매자가 직접 업로드를 끝낸 이미지만 붙일 수 있다. 이미 다른 상품에 붙은 이미지는 쓸 수 없다.
  - 이미지를 교체하면 기존 연결을 모두 풀고 새 목록으로 다시 붙인다. 빈 목록이나 `null`을 보내면 이미지가 모두 제거된다.
  - 썸네일은 표시 순서가 **1**인 이미지다. 순서 1이 없으면 썸네일이 없고 응답은 `null`이다. 기본 이미지는 클라이언트가 채운다.
- **상품 삭제**는 숨김 삭제다. 함께 처리되는 것:
  - 그 상품이 담긴 모든 장바구니 항목을 완전히 삭제한다.
  - 상품–이미지 연결을 삭제하고, 업로드 이미지는 "미사용" 상태로 되돌린다.
  - 주문항목과 리뷰는 그대로 둔다.
- 상품을 삭제해도 진행 중인 주문항목은 그대로 배송하거나 취소할 수 있다. 판매자가 남아 있어 처리할 수 있으므로, 판매자 탈퇴와 달리 삭제를 막지 않는다.
- 삭제된 상품은 목록·상세·장바구니 담기·주문·리뷰 작성/수정·재고 수정의 대상이 아니다. 상품 기준 리뷰 조회도 404가 된다. 경로마다 응답 코드가 다른 문제는 `docs/tracking/findings/product.md`에 있다.
- **카테고리**
  - 관리자만 만들고 지운다. 이름은 유일하고 최대 15자다.
  - 상품이 걸려 있는 카테고리는 삭제를 거절해야 한다. 숨김 삭제된 상품도 걸려 있는 것으로 본다(상품 행이 카테고리를 계속 가리키기 때문이다). 현재는 이 검사가 없어 DB 오류(500)가 난다.

## 상품 목록·검색

- 목록은 항상 페이지 단위다.
- 필터는 키워드, 카테고리 ID, 판매자 ID이고 동시에 쓸 수 있다. 삭제된 상품은 항상 빠진다.
- **키워드**
  - 상품명과 설명을 대상으로 한 전문 검색이다.
  - 공백으로 나뉜 **모든 단어가 들어간 상품만** 나온다(AND). 예: "파란 반팔"은 "파란"과 "반팔"이 둘 다 있어야 한다.
  - `+ - < > ( ) ~ * " @`는 공백으로 바뀐다. 이 문자만 입력하면 결과는 0건이다.
  - 공백만 입력하면 키워드가 없는 것으로 보고 전체 목록을 준다.
  - 두 글자 미만인 단어는 검색어에서 뺀다. 현재는 한 글자 단어가 섞이면 결과가 0건이 될 수 있다(`docs/tracking/findings/product.md`).
- **정렬**
  - 기준: 주문 수, 평점 평균, 조회수, 가격, 등록일. 방향은 오름차순이나 내림차순을 고를 수 있다.
  - 기본값은 등록일 내림차순이다. 같은 값끼리는 상품 ID 내림차순으로 정렬한다.
- **조회수**
  - 상품 상세를 조회할 때마다 1씩 오른다(같은 사람의 반복 조회도 센다).
  - Redis에 모아 두었다가 약 30초마다 DB에 반영한다. 그래서 정렬과 통계에는 늦게 반영될 수 있다.
  - Redis 장애나 반영 실패 도중 장애가 나면 일부 조회수가 사라질 수 있다. 이 정도는 허용한다.

## 재고

- 재고는 상품당 1개이고 항상 0 이상이다. 어떤 경로로도 음수가 되면 안 된다.
- 판매자는 **바뀐 뒤 수량(절대값)**을 입력한다. 증감량이 아니다. 자기 상품이 아니면 403, 삭제된 상품이면 400이다.
- 주문할 때 상품별 주문 수량 합계만큼 차감한다. 같은 상품이 여러 줄이면 합쳐서 계산한다(현재는 장바구니에 같은 상품이 한 줄뿐이라 이런 주문이 생기지 않는다). **한 상품이라도 재고가 모자라면 주문 전체가 실패하고**, 일부만 주문되는 경우는 없다.
- 주문항목을 취소하면 그 항목 수량만큼 재고를 되돌린다.

## 장바구니

- 구매자만 쓴다. 장바구니 항목은 (구매자, 상품) 조합마다 1개다.
- 이미 담긴 상품을 다시 담으면 새 항목을 만들지 않고 수량을 **더한다**.
- 수량 변경은 상품 ID로 대상을 찾고, 바뀐 뒤 수량(1 이상)을 받는다. 삭제는 장바구니 항목 ID로 한다.
- 수량은 항상 1 이상이다. 재고보다 많이 담는 것은 막지 않는다. 재고는 주문할 때 판정한다.
- 장바구니 목록에는 삭제된 상품이 나오지 않는다(상품 삭제 시 항목도 지워진다). 금액은 현재 단가 × 수량이다.

## 주문 생성

- 장바구니 항목을 골라 주문할 수 있고, 상품 상세에서 바로 주문할 수도 있어야 한다. 현재는 **장바구니 항목을 골라서만** 주문할 수 있다(바로 주문은 미구현).
- 한 주문에 항목은 1개 이상이다.
  - 같은 장바구니 항목을 두 번 넣으면 400이다.
  - 자기 장바구니 항목이 아니거나 없는 항목이 하나라도 있으면 주문 전체를 거절한다(남의 항목은 '없음'으로 취급).
  - 삭제된 상품이 섞여 있으면 주문 전체를 거절한다.
- 주문 수량은 장바구니 수량과 달라도 되고, **더 많아도 된다**. 주문한 뒤 장바구니는 이렇게 바뀐다:
  - 주문 수량 ≥ 장바구니 수량 → 장바구니 항목 삭제
  - 주문 수량 < 장바구니 수량 → 장바구니 수량에서 주문 수량만큼 뺀다
- 주문항목에는 주문 시점의 상품 ID, 상품명, 카테고리명, 판매자 ID·닉네임, 설명, 단가, 썸네일 경로가 복사된다. 이후 상품이나 판매자 정보가 바뀌거나 삭제돼도 주문 화면은 복사해 둔 값을 보여준다. 구매자 정보는 복사하지 않고 항상 현재 값을 보여준다.
- 금액 계산:
  - 항목 금액 = 단가 × 수량
  - 최종 항목 금액 = 항목 금액 − 쿠폰 할인액
  - 주문 총액 = Σ 최종 항목 금액. **주문 시점 값**이고, 나중에 항목을 취소해도 바뀌지 않는다.
  - 현재 금액 = 취소되지 않은 항목의 최종 항목 금액 합. 저장하지 않고 주문 상세를 조회할 때 계산해 보여준다(주문 목록에는 주문 총액만 있다).
  - 주문의 항목 수는 취소된 항목을 포함한 전체 개수다.
- 주문 생성은 전부 성공하거나 전부 실패한다. 재고 차감, 쿠폰 사용, 주문 저장, 주문 수 증가, 장바구니 정리 중 하나만 반영되는 경우는 없다.

### 중복 주문 방지

- 주문 생성 요청에는 클라이언트가 만든 `Idempotency-Key`가 반드시 있어야 한다. 이 키가 "같은 논리 요청"을 식별한다. 키는 사용자별, 기능별로 따로 관리한다. 다른 사용자가 같은 키를 써도 서로 영향이 없다.
- 요청 내용이 같은지는 항목 목록(장바구니 항목 ID, 주문 수량, 쿠폰 ID)으로 판정한다. 항목 순서는 따지지 않는다.

| 상황 | 결과 |
|---|---|
| 처음 보는 키 | 주문을 만들고, 이 키의 결과를 24시간 기억한다 |
| 같은 키 + 같은 내용, 이전 요청 성공 | 주문을 새로 만들지 않고 기존 주문 ID를 성공으로 돌려준다 |
| 같은 키 + 같은 내용, 이전 요청 처리 중 | 충돌로 거절. 잠시 후 같은 키로 다시 시도하면 된다 |
| 같은 키 + 다른 내용 | 충돌로 거절(키 재사용 오류) |
| 이전 요청이 실패 | 기록이 지워지므로 같은 키로 다시 시도하면 새로 처리한다 |
| 성공 후 24시간 경과, 또는 "처리 중"으로 5분 넘게 남은 기록 | 만료된 것으로 보고 새 요청으로 처리한다 |

## 주문항목 상태

주문(헤더)에는 상태가 없고, 주문은 삭제되지 않는다. 상태는 주문항목마다 따로 있다.

```
주문완료(ORDERED) ──배송 시작──▶ 배송중(SHIPPED) ──배송 완료──▶ 배송완료(DELIVERED) ──구매확정──▶ 구매확정(PURCHASE_CONFIRMED)
      │
      └──취소──▶ 취소(CANCELED)
```

| 전이 | 누가 | 조건 |
|---|---|---|
| 배송 시작 | 그 상품의 판매자(주문 시점 스냅샷의 판매자) | 현재 `주문완료` |
| 배송 완료 | 같은 판매자 | 현재 `배송중`. 배송완료 시각을 기록한다 |
| 구매확정 | 그 주문의 구매자 | 현재 `배송완료` |
| 취소 | 구매자 **또는** 판매자 | 현재 `주문완료` |

- 위 표에 없는 전이는 모두 거절한다. 예: 배송중인 항목 취소, 구매확정 후 되돌리기, 취소 후 복구.
- 당사자(구매자나 판매자)가 아닌 사람의 요청은 '없음'으로 응답한다(`security.md`의 404/403 기준).
- **이미 취소된 항목을 다시 취소하면 성공(200)으로 응답하고 아무것도 하지 않는다.** 재고·쿠폰·통계 복구는 반복하지 않는다.
- 같은 항목의 상태를 동시에 바꾸려 하면 하나만 성공하고 나머지는 충돌로 거절해 새로고침 후 다시 시도하도록 유도한다.
- 취소하면 한 트랜잭션에서 다음을 처리한다:
  1. 쿠폰을 썼다면 복구
  2. 수량만큼 재고 복구
  3. 상품 주문 수 −1
- 취소해도 주문 총액과 장바구니는 되돌리지 않는다.
- **자동 구매확정**: 배송완료 시각을 서울 날짜로 바꾼 날에 4일을 더한 날의 00:00(서울)까지 구매확정하지 않은 `배송완료` 항목은 자동으로 구매확정된다.
  - 예: 9월 1일 15:00(서울)에 배송완료 → 9월 5일 00:00에 자동 확정
  - 예: 9월 1일 23:59(서울)에 배송완료 → 역시 9월 5일 00:00에 자동 확정
  - 그 전에 구매자가 직접 확정했으면 아무 일도 없다.
  - 현재는 구현되지 않았다. 구매자가 직접 확정해야만 구매확정이 된다.

## 쿠폰

### 이벤트

- 관리자가 만든다. 할인 방식은 정액(`FIXED_AMOUNT`)과 정률(`PERCENT`) 두 가지다.
  - 할인값은 1 이상이고, 정률이면 1~100이다.
  - 최대 할인액(1 이상)은 정률 쿠폰에만 받는다. 현재는 정액 쿠폰에도 필수로 받고 할인액 상한으로 쓴다(`docs/tracking/findings/coupon.md`).
- 발급 수량은 1 이상이다. 시작 시각은 종료 시각보다 앞서야 하고, 종료 시각은 지금보다 뒤여야 한다.
- 이름은 100자 이하, 쿠폰 유효기간은 최대 365일, 발급 종료 시각은 이벤트를 만든 시점부터 최대 1년 뒤다. 현재는 이 상한을 검사하지 않는다(`docs/tracking/findings/error-response.md`).
- 시각은 `yyyy-MM-dd HH:mm:ss` 형식과 시간대(기본 `Asia/Seoul`)로 받는다.
- 쿠폰 유효기간은 분·시간·일 단위의 길이로 정하고, **발급 시각부터** 센다.
- 이벤트는 활성 상태이고 `시작 ≤ 지금 < 종료`일 때만 "열림"이다.
- 관리자는 이벤트를 수정하고 끌 수 있어야 한다. 현재는 이 기능이 없다(`docs/tracking/findings/coupon.md`).
- 구매자는 쿠폰 이벤트 목록과 자기가 받은 쿠폰 목록을 볼 수 있어야 한다. 현재는 두 목록 API가 없어서, 이벤트는 ID로 한 건씩만 조회되고 발급 쿠폰 ID는 발급 응답에서만 얻을 수 있다.

### 발급

- 구매자만 받을 수 있다. 열린 이벤트에서만 가능하다.
- **이벤트 하나당 한 사람 1장**이다. 두 번째 요청은 거절한다.
- **준비된 수량까지 선착순**이다. 다 떨어지면 거절한다.
- 선착순 판정은 Redis에서 원자적으로 한다. 실제 발급 기록은 MySQL에 남긴다.
  - (이벤트, 사용자) 유니크 제약은 1인 1장만 막는다. 수량 한도는 Redis만 판정하므로, Redis가 과거 상태로 복원되면 초과 발급될 수 있다(`docs/tracking/findings/coupon.md`).
  - DB 저장이 실패하면 Redis 쪽 수량과 발급자 표시를 되돌린다. 단, 커밋 단계에서 실패하거나 되돌리는 호출 자체가 실패하면 수량이 1 줄어든 채 남는다(적게 발급된다).
- 이벤트가 Redis에 올라가 있지 않으면 열린 시간이라도 '진행 중인 이벤트가 아님'으로 거절한다. 보통은 시작 10분 전에 미리 올라간다.

### 할인 계산

입력은 항목 금액(단가 × 주문 수량)이다.

- 정액: `할인값`
- 정률: `항목 금액 × 할인율 ÷ 100` (원 미만 버림)
- 최종 할인액 = `min(위 값, 최대 할인액, 항목 금액)`
- 따라서 할인액이 항목 금액보다 클 수 없다. 최종 항목 금액은 0원까지 내려갈 수 있다.
- **할인액이 0원이 되는 쿠폰 적용은 거절해야 한다**(0원 상품, 또는 정률 할인이 1원 미만으로 떨어지는 소액 항목). 사유를 알 수 있는 쿠폰 전용 오류로 응답하는 것이 규칙이다. 현재는 쿠폰 전용 오류가 없어 일반 입력 오류로 주문 전체를 거절한다(현재 응답은 `contracts.md`).

### 사용·복구·만료

- 주문항목 하나에 쿠폰 최대 1장이다. 한 주문에서 같은 쿠폰을 두 번 쓰거나, 자기 쿠폰이 아니거나 없는 쿠폰이면 주문 전체를 거절한다.
- **쿠폰을 쓸 수 있는 조건은 `상태 = 발급됨` 이면서 `지금 < 만료 시각`인 것뿐이다.** 이 조건이 아니면 주문 전체를 거절한다.
- **만료 여부의 기준은 만료 시각이다.** 만료된 쿠폰의 상태를 주기적으로 '만료'로 바꾸는 작업은 없고, 만들지 않는다. 기한이 지난 쿠폰도 상태는 '발급됨'으로 남을 수 있다. 쿠폰을 쓸 수 있는지나 만료됐는지를 판단하는 코드는 항상 만료 시각을 봐야 한다.
- 주문에 쿠폰을 쓰면 상태가 '사용됨'이 된다. 주문항목에는 쿠폰 이름, 방식, 할인값, 최대 할인액, 실제 할인액, 사용 시각이 스냅샷으로 남는다. 이후 조회에서는 할인 전 금액(`linePrice`)과 할인 후 금액(`finalLinePrice`)을 구분해 보여준다.
- 쿠폰을 쓴 주문항목을 취소하면:
  - 만료 시각 전이면 쿠폰이 '발급됨'으로 돌아가 다시 쓸 수 있다.
  - 이미 지났으면 '만료'가 된다. '만료' 상태가 기록되는 경우는 이것뿐이다.

## 리뷰

- 그 상품에 **구매확정된 주문항목이 있는 구매자만** 쓸 수 있다. 조건이 안 되면 거절한다.
- 리뷰는 구매확정된 주문항목 1건마다 1개다. 수량과 관계없이 주문항목 단위로 세므로, 같은 상품을 여러 번 사면 여러 개 쓸 수 있다. 현재는 상품당 한 사람 1개로 제한되고, 두 번째는 거절한다(`docs/tracking/findings/product.md`).
- 별점은 0.0~5.0점, 0.5점 단위다. 내용은 선택이고 최대 255자다.
- 작성자만 수정할 수 있다. 다른 사람의 리뷰는 '없음'으로 응답해 숨긴다. 수정할 때 내용을 빼거나 `null`로 보내면 내용이 비워진다. **삭제는 할 수 없다.**
- 삭제된 상품의 리뷰는 남지만, 새로 쓰거나 고칠 수 없다. 리뷰 목록과 구매자 프로필에는 삭제된 상품의 리뷰가 나오지 않는다. 현재는 작성자 기준 목록과 프로필(최근 5개, 전체 개수)에 나온다(`docs/tracking/findings/product.md`).
- 작성자가 탈퇴하면 리뷰는 남고, 작성자 닉네임 자리에 "삭제된 사용자입니다"가 표시된다.
- 상품 평점 평균 = 리뷰 별점 합 ÷ 리뷰 수다. 리뷰를 쓰거나 별점을 고칠 때 즉시 반영된다. 리뷰가 없으면 0.0이다.
- 리뷰 목록은 최신 작성순만 지원한다. 상품 기준과 작성자 기준 두 가지로 조회한다. 구매자 프로필에는 최근 리뷰 5개와 전체 개수가 들어간다. 수정 여부는 수정 시각이 작성 시각과 다른지로 판단한다.

## 이미지 업로드

1. 판매자가 업로드 URL을 요청한다.
   - 파일 형식은 `image/`로 시작해야 한다.
   - URL은 10분 동안 유효하고, 같은 `Content-Type`으로 PUT해야 한다.
   - 파일은 10MB 이하다. 현재는 크기를 검사하지 않는다(`docs/tracking/findings/product.md`).
2. 판매자가 GCS에 직접 업로드한다.
3. 판매자가 업로드 완료를 등록한다.
   - GCS에 객체가 실제로 있고 형식이 `image/*`일 때만 등록된다.
   - 같은 경로를 같은 사람이 다시 등록하면 기존 등록 결과를 그대로 돌려준다.
   - 이미 다른 사람이 등록한 경로면 거절한다.
   - 아직 아무도 등록하지 않은 경로는 경로를 아는 판매자라면 누구나 자기 것으로 등록할 수 있다. 경로에 무작위 값이 들어가 추측하기 어려우므로 이 수준이면 충분하다고 판단한다.
- 등록된 이미지는 상품에 붙을 때 "사용 중", 상품 연결이 풀리면 "미사용"이 된다. GCS 객체를 지우는 기능은 없다.

## 시간

- 저장은 모두 UTC 시각(Instant)으로 한다.
- 서울 시간대를 쓰는 곳: 가입일(날짜) 표시, 쿠폰 이벤트 입력 기본 시간대, 이미지 경로의 날짜, 자동 구매확정 기한 계산(미구현).
