# 외부 인터페이스 계약 (REST API)

소비자는 HTTP 클라이언트(웹 프론트엔드, k6 스크립트 등)다. 이 문서는 코드만 읽어서는 알기 어려운 것만 적는다.

- 요청·응답 필드와 공통 객체는 요청·응답 DTO(record)가 원본이다: `api/src/main/java/com/ecommerce/api/<도메인>/dto/`
- 기본 주소는 [`operations.md`](operations.md)에 있다. 아래 경로는 기본 주소 뒤에 붙는다.
- 엔드포인트별 권한은 [`security.md`](security.md)의 인가 표, 남의 자원에 대한 404/403 기준도 `security.md`에 있다.
- 목록 응답 필드와 페이지 크기는 [`standards.md`](standards.md)의 "입출력 계약 패턴"에 있다.

## 클라이언트 절차

### 세션과 CSRF
세션 생성, 로그인, 만료와 각 단계의 실패 응답은 [`security.md`](security.md)의 "인증 흐름"에 있다. 클라이언트가 지킬 것:
- 세션 쿠키는 이름에 기대지 말고 쿠키 저장소로 그대로 돌려보낸다.
- `POST`, `PATCH`, `DELETE`에는 `GET /auth/csrf`가 준 `{headerName}: {token}` 헤더를 넣는다.
- 세션이 만료되거나 로그아웃한 뒤에는 `GET /auth/csrf`부터 다시 한다.
- 상태 변경 요청이 403이고 본문에 `code`가 없으면 CSRF 실패일 수 있다. 토큰을 다시 받아 한 번 재시도한다.
- 세션이 만료된 뒤의 첫 상태 변경 요청은 401이 아니라 403(CSRF)이다. 토큰을 다시 받아 재시도하면 401이 온다.

### 주문 생성의 멱등 키
- `POST /orders`에는 `Idempotency-Key` 헤더가 필수다. 1~128자이고 `[A-Za-z0-9._:-]`만 쓴다.
- 사용자가 누른 "주문하기" 한 번마다 새 값을 만들고, **재시도할 때는 같은 값을 쓴다**.
- 같은 키로 같은 내용을 다시 보내면 새로 만들지 않고 기존 주문 ID를 돌려준다. 키의 수명과 판정 규칙은 [`business-rules.md`](business-rules.md)의 "중복 주문 방지"에 있다.
- 본문 검증이 키 검증보다 먼저다. 본문이 잘못됐으면 키가 없어도 `9001`이 먼저 나간다.

## 오류 응답

애플리케이션 오류는 아래 형식이다. **`code`는 4자리 문자열**이다.

```json
{ "code": "7507", "message": "쿠폰이 모두 소진되었습니다." }
```

- `message`는 사용자에게 그대로 보여줄 수 있는 한국어 문장이다. 같은 `code`라도 상황에 따라 더 구체적인 문장이 올 수 있다.
- 클라이언트의 분기 처리는 **HTTP 상태와 `code`로만** 한다. `message` 문자열로 분기하지 않는다.

### 오류 매핑

| 상황 | 상태 | 본문 |
|---|---|---|
| 로그인 필요(세션 없음·만료), 로그인 실패 | 401 | 없음 |
| 역할 부족, CSRF 실패 | 403 | Spring Boot 기본 오류 JSON(`timestamp`, `status`, `error`, `path`). `code` 없음 |
| 부하테스트 헤더 인증 실패 | 401 | Spring Boot 기본 오류 JSON. `code` 없음 |
| 본문·쿼리 필드 검증 실패(`@NotNull`, `@Min` 등) | 400 | `9001`, 위반한 필드의 한국어 메시지. 필드에 묶이지 않은 검증이면 `"요청 값이 올바르지 않습니다."` |
| 본문이 JSON이 아니거나 필드 타입이 틀림, 본문 필드 사이의 조건 위반 | 400 | `9001`, `"요청 Body 읽기 실패"` |
| 쿼리 파라미터 타입 오류(enum, 숫자) | 400 | `9001`, 프레임워크가 만든 영문 메시지 |
| 경로 변수 타입 오류 | 400 | `9001`, `"요청 인자 타입 오류"` |
| 업무 오류 | `ErrorCode`의 상태 | 해당 `code`와 메시지. 엔드포인트별 목록은 아래에 있다 |
| 주문항목 동시 상태 변경 충돌 | 409 | `3004`. 새로고침한 뒤 다시 시도한다 |
| 쿼리 파라미터 사이의 조건 위반 | 500 | `9999`, `"잠시 후 다시 시도해주세요."` |
| 로그인한 상태에서 없는 경로, 허용하지 않는 메서드, 잘못된 `Content-Type` | 500 | `9999`, `"잠시 후 다시 시도해주세요."` |
| 그 밖에 처리하지 못한 예외(일부 잘못된 입력, 동시 요청의 유니크 제약 위반 등) | 500 | `9999`, `"잠시 후 다시 시도해주세요."` |
| 보안 필터 단계의 서버 오류(세션 저장소 장애 등) | 500 | Spring Boot 기본 오류 JSON. `code` 없음 |

## 엔드포인트

"분기할 오류"에는 클라이언트가 사용자에게 다르게 안내할 업무 오류만 적는다. 검증 실패(400 `9001`), 인증·권한 실패, 서버 오류는 위의 오류 매핑을 따른다.

### Auth
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `GET /auth/csrf` | 세션을 만들고 CSRF 토큰을 준다 | — |
| `POST /auth/login` | 현재 세션을 인증한다 | 401(본문 없음. 실패 사유를 구분하지 않는다) |
| `POST /auth/logout` | 세션을 무효화한다 | — |

### User
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /users` | 가입(구매자, 판매자) | 409 `1001`(이메일 중복. 탈퇴한 사용자의 이메일 포함) |
| `GET /users/{userId}` | 사용자 프로필 | 404 `1000`(없음, 탈퇴) |
| `GET /users/me` | 내 프로필 | — |
| `GET /users` | 회원 목록(관리자) | — |
| `PATCH /users/me` | 닉네임 변경 | — |
| `PATCH /users/me/password` | 비밀번호 변경. 성공하면 현재 세션이 로그아웃된다 | 401 `1003`(기존 비밀번호 불일치) |
| `POST /users/me/withdraw` | 탈퇴. 성공하면 현재 세션이 로그아웃된다 | 401 `1003`, 403 `1004`(판매자에게 진행 중인 주문항목 있음) |

### Product
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /products` | 상품 등록 | 400 `2001`(카테고리 없음), 404 `8003`(이미지 없음, 남의 이미지), 400 `8004`(이미 다른 상품에 붙은 이미지) |
| `GET /products` | 상품 목록·검색 | — |
| `GET /products/{productId}` | 상품 상세. 조회수가 1 오른다 | 404 `2000`(없음, 삭제됨) |
| `PATCH /products/{productId}` | 설명·단가 수정 | 403 `2002`(내 상품 아님), 404 `2000` |
| `PATCH /products/{productId}/images` | 이미지 목록 교체 | 등록과 같은 이미지 오류, 403 `2002`, 404 `2000` |
| `DELETE /products/{productId}` | 상품 삭제 | 403 `2002`, 404 `2000` |
| `POST /products/category` | 카테고리 생성(관리자) | 409 `2005`(이름 중복) |
| `GET /products/category` | 카테고리 목록 | — |
| `DELETE /products/category/{categoryId}` | 카테고리 삭제(관리자) | 400 `2001`(없음), 500 `9999`(상품이 걸려 있음) |
| `PATCH /products/inventory` | 재고를 바뀐 뒤 수량으로 수정 | 400 `2004`(삭제된 상품), 403 `2002` |

### Media
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /media/upload-url` | GCS 업로드용 서명 URL 발급 | 400 `8001`(이미지 형식 아님) |
| (GCS 직접 업로드) | `PUT {uploadUrl}`. 조건은 [`business-rules.md`](business-rules.md)의 "이미지 업로드" | 헤더가 다르거나 URL이 만료되면 GCS가 403 |
| `POST /media/upload-complete` | 업로드 완료 등록 | 404 `8000`(GCS에 객체 없음), 400 `8001`, 400 `8002`(다른 사람이 이미 등록한 경로) |
| `GET /media/uploaded-images` | 업로드 이미지 목록(관리자) | — |

| `GET /cart-items` | 내 장바구니 | — |

### Order
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /orders` | 장바구니 항목으로 주문 생성(멱등 키 필수) | 아래 표 |
| `GET /orders/me` | 내 주문 목록 | — |
| `GET /orders/{orderId}` | 주문 상세 | 404 `3000`(없음), 404 `3001`(남의 주문) |

`POST /orders`의 오류:

| 상황 | 상태·코드 |
|---|---|
| 키 없음 / 형식 오류 | 400 `9100` / 400 `9101` |
| 같은 키, 다른 내용 | 409 `9102` |
| 같은 키 요청이 처리 중 | 409 `9103`(잠시 후 같은 키로 재시도) |
| 한 주문에 같은 장바구니 항목 두 번 | 400 `9001` |
| 장바구니 항목 없음, 남의 항목 | 404 `7000` |
| 삭제된 상품 포함 | 대개 404 `7000`(상품을 지우면 장바구니 항목도 지워진다). 삭제와 주문이 겹칠 때만 400 `2004` |
| 같은 쿠폰 두 번 | 400 `7509` |
| 쿠폰 없음, 남의 쿠폰 | 404 `7510` |
| 쓸 수 없는 쿠폰(사용됨, 만료) | 400 `7501` |
| 할인액이 0원이 되는 쿠폰 | 400 `9001`. 메시지는 경우마다 다르다 |
| 재고 부족(재고 행이 없는 비정상 데이터도 같음) | 400 `2501` |

### OrderItem
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `GET /order-items` | 주문항목 목록. 구매자는 `orderId`, 판매자는 `sellerId` 중 하나만 준다 | 404 `0001`(역할 불일치), 404 `3000`(남의 주문), 404 `3001`(`sellerId`가 본인이 아님) |
| `GET /order-items/{orderItemId}` | 주문항목 상세(구매자, 해당 판매자) | 404 `3002`(없음), 404 `3001`(당사자 아님) |
| `PATCH /order-items/{id}/ship` | 배송 시작 | 400 `3003`(상태 전이 불가), 404 `3002`/`3001`, 409 `3004` |
| `PATCH /order-items/{id}/deliver` | 배송 완료 | 위와 같음 |
| `PATCH /order-items/{id}/confirm` | 구매확정 | 위와 같음 |
| `PATCH /order-items/{id}/cancel` | 취소(구매자, 해당 판매자). 이미 취소된 항목도 200 | 위와 같음 |

### Coupon
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /coupons/events` | 쿠폰 이벤트 생성(관리자) | — |
| `GET /coupons/events/{couponEventId}` | 이벤트 조회(남은 수량 포함) | 404 `7500` |
| `POST /coupons/events/{couponEventId}/issue` | 선착순 발급 | 400 `7503`(열린 이벤트 아님), 400 `7506`(이미 발급), 400 `7507`(소진) |

- `remainingQuantity`는 이벤트가 Redis에 올라가 있지 않으면 `null`이다. 발급 시작 10분 전보다 이를 때(적재는 최대 30초 늦을 수 있다), 종료 10분 뒤부터, Redis를 잃고 다시 적재하기 전이 그렇다.
- 주문에 쓸 `couponIssuedId`는 발급 응답에서 얻는다.

### Review
| 호출 | 설명 | 분기할 오류 |
|---|---|---|
| `POST /products/{productId}/reviews` | 리뷰 작성 | 403 `6001`(구매확정 이력 없음), 403 `6002`(이미 작성), 404 `2000`(없음, 삭제된 상품) |
| `GET /reviews` | 상품 기준(`searchBy=PRODUCT`)이나 작성자 기준(`WRITER`) 리뷰 목록 | 404 `2000`(없음, 삭제된 상품), 404 `1000`(없음, 탈퇴한 작성자) |
| `PATCH /reviews/{reviewId}` | 리뷰 수정(별점과 내용을 통째로 바꾼다) | 400 `2004`(삭제된 상품), 404 `6000`(없음), 404 `6003`(남의 리뷰) |

- 별점 필드 `halfStars`는 0.5점 단위를 정수로 나타낸 값(0~10)이다. 화면 별점 = `halfStars` ÷ 2.
