## 남은 작업 (우선순위 순)

1. **주문항목 취소의 쿠폰 락 순서를 생성과 같게 맞추기**: 가장 먼저 처리한다. `findings/order.md`의 "주문항목 취소가 쿠폰 행 락을 생성과 반대 순서로 잡는다" 참고.
2. **Redis 장애 대응 보강**: Redis가 죽거나 과거 상태로 복원될 때의 정합성과 대체 동작(fallback)을 함께 설계한다. `findings/coupon.md`와 `findings/product.md`의 아래 항목을 묶어서 본다.
   - 쿠폰 발급 수량 한도를 Redis만 판정해서 초과 발급될 수 있다
   - 쿠폰 발급 실패 때 Redis 수량을 되돌리지 못하는 경우가 있다
   - 쿠폰 이벤트를 만들 때 Redis 적재가 커밋 전에 일어나고, 실패하면 생성이 실패한다
   - Redis 장애 시 공개 상품 상세 조회가 실패한다
3. **오류 응답 결함 수정**: `findings/error-response.md`의 항목(방향 미정 두 개 제외)과 아래를 함께 본다.
   - 로그인한 사용자의 없는 경로·허용하지 않는 메서드·잘못된 `Content-Type`이 404·405·415가 아니라 500이 되는 문제(전역 핸들러가 모든 예외를 잡음)
   - 먼저 조회하고 저장하는 경로가 동시 요청에서 유니크 제약 위반으로 500이 되는 문제: 가입(이메일), 카테고리 생성(이름), 이미지 부착(업로드 이미지), 리뷰 작성(작성자·상품). 장바구니와 쿠폰 발급만 전용 코드로 바꾼다
   - 보안 필터 단계(세션 저장소 장애 등)의 500이 `{code, message}`가 아니라 `code` 없는 Spring Boot 기본 오류 JSON으로 나가는 문제
4. **빠진 기능**: 규칙은 `business-rules.md`의 해당 절에 있다.
   - 상품 상세에서 바로 주문
   - 자동 구매확정. 여러 인스턴스에서 동시에 돌아도 안전해야 한다(구현 주의점은 order 모듈 문서)
   - 상품이 걸린 카테고리 삭제 거절(400 또는 409, 전용 오류 코드)
   - 할인액 0원 쿠폰 적용 거절(쿠폰 전용 오류 코드와 사유 메시지)
   - 쿠폰 이벤트 목록 조회, 내 쿠폰 목록 조회
   - 쿠폰 이벤트 수정·비활성화(관리자)
5. **테스트가 없는 영역에 테스트 추가**: 인증·인가 매트릭스, 상품·검색, 쿠폰 발급, 리뷰 작성·수정, 사용자 탈퇴.
   - 장바구니의 남은 경계 사례: 삭제된 상품 담기
   - 장바구니 테스트에 `@DisplayName`(한국어) 추가(`api/CLAUDE.md` 규약)
6. **그 밖의 미해결 문제**: 요구사항과 다른 현재 동작과 결함 가운데 위에 없는 것은 `findings/`의 영역별 파일에 있다(우선순위 미정).
