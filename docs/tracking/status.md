## 남은 작업 (우선순위 순)

1. **기존 문서 전면 개편**: 문서·코드·k6 동기화 작업으로 진행 중이다(`docs/tracking/renewal.md`). 남은 것은 `README.md`다.
2. **만료된 멱등 기록 삭제를 조건부로 바꾸기**: 가장 먼저 처리한다. 같은 멱등 키로 주문이 두 건 생길 수 있다. `findings/order.md`의 "만료된 멱등 기록을 id만 보고 지워서, 같은 키로 주문이 두 건 생길 수 있다" 참고.
3. **주문항목 취소의 쿠폰 락 순서를 생성과 같게 맞추기**: 2번 다음에 처리한다. `findings/order.md`의 "주문항목 취소가 쿠폰 행 락을 생성과 반대 순서로 잡는다" 참고.
4. **Redis 장애 대응 보강**: Redis가 죽거나 과거 상태로 복원될 때의 정합성과 대체 동작(fallback)을 함께 설계한다. `findings/coupon.md`와 `findings/product.md`의 아래 항목을 묶어서 본다.
   - 쿠폰 발급 수량 한도를 Redis만 판정해서 초과 발급될 수 있다
   - 쿠폰 발급 실패 때 Redis 수량을 되돌리지 못하는 경우가 있다
   - 쿠폰 이벤트를 만들 때 Redis 적재가 커밋 전에 일어나고, 실패하면 생성이 실패한다
   - Redis 장애 시 공개 상품 상세 조회가 실패한다
5. **오류 응답 결함 수정**: `findings/error-response.md`의 항목과 아래를 함께 본다.
   - 쿼리 파라미터 조건 위반이 500으로 나가는 문제
   - 본문 교차 검증 오류가 `"요청 Body 읽기 실패"`로 뭉개지는 문제. 필드 사이 조건은 record의 `@AssertTrue`로 옮긴다(`standards.md`)
   - 쿼리 파라미터 타입 오류(enum, 숫자)에 영문 프레임워크 메시지가 노출되는 문제
   - 로그인한 사용자의 없는 경로·허용하지 않는 메서드·잘못된 `Content-Type`이 404·405·415가 아니라 500이 되는 문제(전역 핸들러가 모든 예외를 잡음)
   - 먼저 조회하고 저장하는 경로가 동시 요청에서 유니크 제약 위반으로 500이 되는 문제: 가입(이메일), 카테고리 생성(이름), 이미지 부착(업로드 이미지), 리뷰 작성(작성자·상품). 장바구니와 쿠폰 발급만 전용 코드로 바꾼다
   - 보안 필터 단계(세션 저장소 장애 등)의 500이 `{code, message}`가 아니라 `code` 없는 Spring Boot 기본 오류 JSON으로 나가는 문제
6. **빠진 기능**
   - 상품 상세에서 바로 주문(장바구니를 거치지 않는 주문 생성)
   - 자동 구매확정(배송완료 서울 날짜 + 4일의 00:00까지 확정하지 않은 주문항목. 예: 9/1 15:00 배송완료 → 9/5 00:00). 여러 인스턴스에서 동시에 돌아도 안전해야 한다
   - 상품이 걸린 카테고리 삭제 거절(400 또는 409, 전용 오류 코드). 숨김 삭제된 상품도 "걸려 있음"으로 본다(상품 행이 FK로 카테고리를 계속 가리키기 때문). 그래서 과거 상품이 가리키는 카테고리는 지울 수 없다
   - 할인액 0원 쿠폰 적용 거절(쿠폰 전용 오류 코드와 사유 메시지)
   - 쿠폰 이벤트 목록 조회(구매자가 이벤트를 찾을 수 있게. 지금은 ID로 한 건씩만 조회된다)
   - 내 쿠폰 목록 조회(지금은 `couponIssuedId`를 발급 응답에서만 얻을 수 있어, 놓치면 주문에 쓸 수 없다)
7. **테스트가 없는 영역에 테스트 추가**: 인증·인가 매트릭스, 상품·검색, 쿠폰 발급, 리뷰, 사용자 탈퇴.
   - 장바구니의 남은 경계 사례: 삭제된 상품 담기
   - 장바구니 테스트에 `@DisplayName`(한국어) 추가(`api/CLAUDE.md` 규약)
